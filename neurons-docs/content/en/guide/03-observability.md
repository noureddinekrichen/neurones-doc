Beyond application monitoring itself, Neurons also covers application logs, real end-user experience, and a dedicated workspace for cross-cutting incident investigation.

## Logs {#logs}

The "Logs" screen gives access to recent application logs, filterable by severity level (info, warning, error, etc.) and by time window. It's designed to be used alongside traces: a trace shows how a request unfolded, logs provide the textual detail the application chose to write at a given moment.

## Events {#events}

The "Observability Event Center" centralizes every event generated by the platform: a threshold breach on a service, a health rule violation, etc. Each event has a severity and follows an explicit lifecycle:

- **Open** — the event was just detected and hasn't been handled yet.
- **Acknowledged** — someone has taken ownership of the investigation.
- **Resolved** — the problem is fixed; only from this point does an event become eligible for automatic purging.
- **Suppressed** — the event is explicitly set aside, for example because it's known and has no impact.

An open or acknowledged event is never automatically purged, no matter its age — only the retention of resolved events is configurable.

## User Experience (RUM) {#rum}

This screen, labeled "Browser Performance" in the interface, measures the real experience of a web application's visitors (Real User Monitoring). It combines several types of analysis:

- **Web Vitals** — the standard perceived-performance indicators: LCP, INP, CLS, FCP, and TTFB, with percentiles and a good / needs improvement / poor breakdown.
- **Load time distribution** — a histogram of page load durations with percentile markers.
- **Sessions and replay** — every user session can be reconstructed as a chronological journey, and some sessions have a replayable recording.
- **Frustration signals** — automatic detection of rage clicks, dead clicks, and error clicks, which reveal a degraded experience even without a visible technical error.
- **Geographic and device breakdown** — browser, operating system, device, or geographic region.
- **Correlation with business transactions** — the ability to see which backend business transactions are triggered by a given page, and vice versa.

## Troubleshoot {#troubleshoot}

The "Troubleshoot" screen is a cross-cutting workspace for investigating an ongoing problem, organized into four tabs:

| Tab | What it shows |
|---|---|
| **Slow Response Times** | Breakdown of requests by latency bucket (normal, slow, very slow, stalled) and the main contributors to those slowdowns. |
| **Errors** | The dominant error signatures over the selected window, with their trend. |
| **Health Rule Violations** | Health rules currently in violation, with the context needed to investigate. |
| **War Rooms** | Manual tracking of open incidents, with AI-generated postmortem reports. |
{firstcol="30"}

A "comparison" mode lets you contrast the current time window against the equivalent previous window, which helps distinguish normal variation from a genuine degradation. Any identified item can be opened directly in the Traces, Errors, or Logs screens, already filtered to the right context.
